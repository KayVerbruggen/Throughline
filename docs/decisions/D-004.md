title: Reference components by title-handle in guards
status: accepted
trace:
  - UC-008
context: behaviour-formalisation layer
concern: guards must name component state in a form that stays readable in plain text and diffs
decision: to reference a component by the camelCase handle of its title (e.g. applicationStore.dirty)

In the behaviour-formalisation layer, facing guards must name component state in a form that stays readable in plain text and diffs, we decided to reference a component by the camelCase handle of its title (e.g. applicationStore.dirty) and not to reference components by their stable id (e.g. C-003.dirty) to achieve guard expressions that read naturally in a file and a code review, accepting that renaming a component silently orphans every guard that used its old handle.
