In the project storage layer, facing models need to live in the user's own git repo and stay diff-, merge-, and review-friendly, we decided to store each artifact as a YAML-frontmatter + markdown file, one per artifact, under per-kind folders and not to keep the whole project in a single binary or SQLite database to achieve git-native models that both humans and LLMs can read and diff cleanly, accepting no referential integrity at write time — dangling ids are tolerated on read and only surfaced in the UI.
