The LLM client foundation (`src/llm/`). A deliberately narrow, provider-agnostic `LlmClient` interface — one `complete(prompt)` call in, one text result out, no chat history or streaming — with a direct-fetch Anthropic implementation, chosen by a `createLlmClient()` factory that mirrors the storage layer's runtime split. Configuration (API key + model) lives in `localStorage`, scoped to the app's webview profile rather than the project folder, so the key never lands in the user's git repo. Failures are returned as a Result rather than thrown, matching the Expression Engine, so feature code can surface them inline. Its UI so far is the settings dialog (a gear in the top bar) where the key and model are entered and a "Test connection" button exercises the client end-to-end (the gear also carries a dot while no key is set), plus guard- and effect-suggestion affordances in the Behaviour view.

On top of the client sit two feature-enabling pieces. `completeJson` wraps `complete` for structured tasks: it extracts JSON from the reply, validates it with a caller-supplied function, and retries once with the error fed back so the model can self-correct — the caller's validator is where *semantic* checks live, so those failures also drive the retry. Two suggestion features are built on it, sharing one variable-proposal layer (`llm/variables.ts`: resolve a proposed variable's component handle, augment a clone of the project with it, drop redundant proposals). **Guard suggestion** turns an alternate branch's plain-language condition into a formal guard, type-checked with the Expression Engine's `analyzeGuard`. **Effect suggestion** turns an activity's label into a list of assignments, each type-checked with `analyzeEffect`; an empty list is a valid answer (the activity is a pure named step). Either may propose *new* variables — most naturally a component's mode enum for effects — and accepting creates them alongside applying the guard/effects, so an invalid one is never offered. Building on both, **whole-flow formalization** (`formalizeFlow`) sends an entire flow to the model in one call and gets back a coherent plan — a guard for every unformalized branch and effects for every unformalized activity over *one* shared set of new variables — rather than looping the per-item suggesters, each of which would invent its own state. The validator type-checks every guard and effect against the augmented project (throwing an item-located message so one bad item drives the retry with specific feedback), drops already-formal items instead of clobbering them, and prunes proposed variables no kept expression references; a review panel in the Behaviour view shows the plan before `applyFormalization` applies it atomically. Scaling that up, **whole-project formalization** (`formalizeAllFlows`) runs one *sequential* pass over every use case's flow, threading an evolving in-memory project through each step so a later flow reuses the variables an earlier one introduced rather than minting its own — the reason it can't fan out in parallel. It is best-effort (a flow that fails is recorded and the pass continues) and skips flows with nothing pending (including those whose shared activities an earlier flow already formalized); a batch review shows every flow's proposal or error, and a single "Accept all" persists the accumulated changes (all-or-nothing, since threaded plans interdepend).

A different shape of feature sits beside the formalization tools: the **model critic** (`critiqueProject`), a *read-only* whole-project review. `describeProject` (in `llm/projectContext.ts`) renders a compact, id-tagged summary of every artifact with its text, trace links, and mechanical coverage flags; the model returns judgement-level `Finding`s (severity, category, title, detail, artifact refs) that a mechanical check can't — vague or untestable requirements, conflicts, load-bearing choices with no decision, undefined domain terms. It complements the mechanical `model/trace.ts` warnings rather than duplicating them; `validateCritique` is lenient (findings are advisory) but drops references to ids that don't exist so each one drives a working jump-link. Surfaced as a "✨ Review model" button + dismissible findings panel in the Traceability view. Still to build on this base: natural-language authoring, prototype drafting, and reverse-engineering.
