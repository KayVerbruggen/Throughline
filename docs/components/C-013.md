The LLM client foundation (`src/llm/`). A deliberately narrow, provider-agnostic `LlmClient` interface — one `complete(prompt)` call in, one text result out, no chat history or streaming — with a direct-fetch Anthropic implementation, chosen by a `createLlmClient()` factory that mirrors the storage layer's runtime split. Configuration (API key + model) lives in `localStorage`, scoped to the app's webview profile rather than the project folder, so the key never lands in the user's git repo. Failures are returned as a Result rather than thrown, matching the Expression Engine, so feature code can surface them inline. Its only UI so far is the settings dialog (a gear in the top bar) where the key and model are entered and a "Test connection" button exercises the client end-to-end; the top-bar gear also carries a dot while no key is set. Higher-level features (guard/effect suggestion, prototype drafting, reverse-engineering) will build their prompts on top of this without depending on the transport or provider.
